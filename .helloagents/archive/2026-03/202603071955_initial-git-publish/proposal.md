## 1. 需求

### 背景
当前目录还不是 Git 仓库，用户已经准备好远程仓库、SSH 密钥和目标远程地址，希望把现有项目作为首次提交推送到 GitHub。

### 目标
- 在当前目录初始化 Git 仓库。
- 将 `README.md` 纳入首次提交并生成 `main` 分支。
- 绑定远程仓库 `git@github.com:GAtomis/codex-hub.git`。
- 将本地首次提交成功推送到远程 `origin/main`。

### 约束条件
```yaml
时间约束: 本轮直接完成首次提交与推送。
性能约束: 无特殊要求。
兼容性约束: 使用当前本机已安装的 Git 与已配置的 SSH 凭据。
业务约束: 优先按用户给出的 Git 命令顺序执行；若现场与预期不一致，则做最小化调整并保留结果可追溯。
```

### 验收标准
- [ ] 当前目录存在可用的 Git 仓库，默认分支为 `main`。
- [ ] `README.md` 已被提交到本地首次提交中。
- [ ] 远程 `origin` 指向 `git@github.com:GAtomis/codex-hub.git`。
- [ ] `git push -u origin main` 执行成功，远程建立上游关系。

## 2. 方案

### 技术方案
先检查当前目录是否已经存在 Git 元数据与远程配置，再按用户指定流程执行 `git init`、`git add README.md`、`git commit`、`git branch -M main`、`git remote add origin` 与 `git push -u origin main`。若执行过程中发现本地现场与预期不一致，则仅做保障成功所需的最小调整。

### 影响范围
```yaml
涉及模块:
  - 仓库元数据: 新建 `.git/` 并写入首次提交历史与远程配置
  - 工作目录文档: `README.md` 被纳入首次提交
预计变更文件: 2
```

### 风险评估
| 风险 | 等级 | 应对 |
|------|------|------|
| 远程推送失败（认证/网络/仓库状态） | 中 | 保留本地提交结果，输出失败原因并停止后续远程写入。 |
| 现场已存在非预期 Git 配置 | 低 | 先检查本地状态，必要时只做最小调整，不覆盖用户未授权内容。 |

### initial-git-publish#D001: 首次提交严格按用户给定流程推进
**日期**: 2026-03-07
**状态**: ✅采纳
**背景**: 用户已经明确给出完整 Git 操作序列，且远程仓库和 SSH 凭据都已准备完成。
**选项分析**:
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: 按用户给定命令顺序执行 | 与用户预期一致，变更最少，可追溯性强 | 若现场异常，需要临场做少量兼容处理 |
| B: 自行改写为其他 Git 流程 | 可根据现场自由调整 | 偏离用户要求，增加不必要差异 |
**决策**: 选择方案 A。
**理由**: 本任务属于明确的仓库发布操作，遵循用户给定命令序列最稳妥，且只需在现场与预期不符时做最小补充。
**影响**: 影响当前目录 Git 元数据、本地提交历史和远程仓库 `origin/main`。
