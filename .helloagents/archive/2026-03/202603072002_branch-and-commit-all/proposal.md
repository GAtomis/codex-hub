## 1. 需求

### 背景
当前仓库只有 `README.md` 被提交到 `main`，其余项目文件仍处于未跟踪状态。用户希望将当前剩余内容全部纳入版本控制，并额外切换到指定分支 `feat-项目迭代v2-20260307` 继续后续迭代。

### 目标
- 创建并切换到分支 `feat-项目迭代v2-20260307`。
- 将当前仓库全部未提交内容纳入一次新的本地提交。
- 保留现有 `main` 上的首次提交历史。

### 约束条件
```yaml
时间约束: 本轮直接完成分支切换与全部本地提交。
性能约束: 无特殊要求。
兼容性约束: 使用当前本机 Git 环境，不修改既有远程配置。
业务约束: 未指定 commit message 时，采用通用提交信息 `chore: commit remaining files`。
```

### 验收标准
- [ ] 当前分支为 `feat-项目迭代v2-20260307`。
- [ ] 所有当前未提交文件均被纳入新提交。
- [ ] 本地工作树提交后为干净状态（忽略规则生效的文件除外）。

---

## 2. 方案

### 技术方案
先检查当前 Git 分支与工作树状态，然后从 `main` 创建并切换到目标分支，再执行 `git add -A` 与新的本地提交。提交完成后通过 `git status`、`git log` 验证分支与提交结果。

### 影响范围
```yaml
涉及模块:
  - Git 分支: 新建并切换到 `feat-项目迭代v2-20260307`
  - 工作目录文件: 当前所有未提交文件被纳入版本控制
  - 本地提交历史: 追加一条新提交记录
预计变更文件: 全部未提交文件
```

### 风险评估
| 风险 | 等级 | 应对 |
|------|------|------|
| 提交内容包含不应入库的文件 | 中 | 以当前 `.gitignore` 规则为准，只提交 Git 视角下未忽略文件；执行后汇报实际纳入内容。 |
| 目标分支已存在 | 低 | 先检查分支列表；若已存在则直接切换过去，避免重复创建。 |

---

## 3. 核心场景

### 场景: 在新迭代分支上收敛当前工作区
**模块**: 仓库版本管理
**条件**: 当前仓库存在未跟踪或未提交文件，且 `main` 已有基础提交。
**行为**: 新建并切换到目标分支，随后一次性提交剩余项目文件。
**结果**: 后续开发可直接在新分支上继续推进，不污染 `main` 当前状态。

## 4. 技术决策

### branch-and-commit-all#D001: 先切分支再提交全部内容
**日期**: 2026-03-07
**状态**: ✅采纳
**背景**: 用户希望“全部提交”并指定一个新的功能分支名称。
**选项分析**:
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: 先在 `main` 提交，再新建分支 | 操作直观 | 新提交会先落在 `main`，不符合分支隔离的常见预期 |
| B: 先切到目标分支，再提交全部内容 | 提交直接归属目标分支，分支边界更清晰 | 需要额外处理目标分支已存在的情况 |
**决策**: 选择方案 B。
**理由**: 用户明确提出需要切新分支，按常规协作流程应让本次“全部提交”直接落到新分支上，避免 `main` 额外增加迭代性提交。
**影响**: 影响本地 Git 分支结构与后续提交落点。
